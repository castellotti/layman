# Changelog

## Unreleased

- Moved Layman's own database and runtime config out of Claude Code's `~/.claude` directory into a harness-agnostic XDG data dir (`config/paths.ts`), resolved as `$LAYMAN_DATA_DIR` -> `$XDG_DATA_HOME/layman` -> `~/.local/share/layman`. Neither file is Claude Code's - the database records events from every harness and the config is Layman's alone - so a user who runs only Codex, Vibe, or pi no longer has Layman scatter state into a tool they never installed. On first launch `migrateLegacyData()` (run before `loadConfig`/`openDatabase`) **copies** an existing `~/.claude/layman.{db,json}` to the new location when the new file is absent: non-destructive (originals kept as a backup), idempotent (guarded on "new file absent", never clobbers live data), and it doubles as a restore path - dropping a backed-up `layman.db` into `~/.claude` is adopted on next launch. docker-compose bind-mounts `${HOME}/.local/share/layman` into the container, so the database stays a **host** file (never a Docker volume) exactly as before and the DELETE journal-mode reasoning is unchanged; the Makefile `mkdir -p`s it before `up` so the mount source exists
- Added a "N recorded sessions kept" note to **Settings -> Harness** for any harness that has recorded history in the database but is no longer installed on this machine (e.g. after restoring a home-folder backup onto a fresh OS, or uninstalling a harness). Recorded events are keyed by harness (`agent_type`) but never depend on that harness still being present, so removing OpenCode, Cline, etc. never loses their history; the setup-status route now surfaces per-harness counts via `countRecordedSessionsByAgentType` so the UI can say so explicitly. Rescanning (the existing status refresh) re-checks harness presence on every call
- Fixed the native pi passive watcher double-recording sessions that the pi extension already records live. `NativePiSource` is watched unconditionally, so a native pi run with the extension installed - the common case, since Layman offers the extension as an installable client - was recorded twice: once over hooks, once by tailing the same `~/.pi/agent/sessions` transcript, each with independent `randomUUID` ids the `source === 'live'` dedupe can't collapse. `NativePiSource` now returns no root when the extension file (`~/.pi/agent/extensions/layman/index.ts`) is present, so the live extension owns native pi and the watcher covers only native pi *without* it. Glove pi is unaffected - a sandbox never runs the host's extension and can't reach Layman over the network, which is why it must be tailed
- Fixed a resumed pi session never being monitored again after a 15-minute idle timeout. `cleanupEndedSessions` tombstoned the session (poll timer cleared, entry left in the map) but nothing revived it, and `scanExistingSessions` skips paths already in the map, so new turns after the gap were silently dropped - a regression from `VibeSessionWatcher`, which resurrects tombstoned sessions. The pi watcher now does the same via `tryResumeSession`: when a tombstoned session's transcript grows again it emits a `resumed` session_start, restarts the poll timer, and catches up
- Hardened the pi watcher's incremental emission against a re-parse reordering already-committed events (as parallel tool calls finishing out of order can), which array-position slicing could duplicate or drop. Emission now dedupes on the parser's deterministic event id via a per-session `Set` rather than a running committed-event count. Also de-duplicated the `<timestamp>_<sessionId>.jsonl` filename parsing that existed verbatim in both `pi/watcher.ts` and `transcript-pi.ts` into a shared `sessionIdFromPiFilename()`
- Added passive monitoring of glove-sandboxed **pi** sessions, alongside the existing glove/Vibe support. pi persists each session as a format-version-3 JSONL tree at `~/.pi/agent/sessions/<encoded-cwd>/<ts>_<id>.jsonl`, which Layman already parses for historical import, so a new `PiSessionWatcher` (`pi/watcher.ts`) reuses `parsePiTranscript()` to tail those files incrementally - no pi extension and no second parser. `GloveSource` now emits a pi root for any sandbox whose home contains `.pi/agent/sessions/` in addition to its Vibe root (a sandbox may run both), and a new `NativePiSource` covers native `~/.pi`. Each watcher filters `roots()` to the agent type it parses, so the two share one glove source. Read-only "outside looking in", same posture as the Vibe source: nothing written into a sandbox, no egress, the mount stays `:ro`. Logging only - interception/blocking of a sandboxed harness remains a separate forwarder mechanism, out of scope here
- Extended **Settings -> Data -> Import session history** to discover gloved pi sessions. The scan previously looked only under the native `~/.pi/agent/sessions`, so a pi run inside a glove sandbox that was never monitored live (glove monitoring off during the run, or Layman down) was invisible to it. `discoverTranscriptFiles()` now also scans the pi watch roots the passive watchers report (threaded from `server.ts` as `gloveSource.roots()`, empty when glove is disabled), and the env id rides through to the imported session's name so a gloved import is tagged just like a passively-watched one. Only pi is imported from a sandbox - claude-code isn't run under glove and Vibe has no history importer - and a session already recorded live is still skipped rather than duplicated, so native import is unchanged
- Changed the default glove sessions directory from `~/.glove/sessions` to `~/.glove/envs`, matching glove's per-environment on-disk layout (`~/.glove/envs/<env-id>/home/`), and the docker-compose read-only mount with it. The `<env-id>` (`pi-local`, `pi-local-vibe`, ...) is used as the UI label so gloved sessions stay distinguishable from native ones
- Added passive monitoring of glove-sandboxed harnesses ([glove](https://github.com/castellotti/glove) runs a harness inside a Docker/Podman container with a per-environment fake home persisted on the host). Off by default under **Settings -> Connection -> glove sandboxes**; when enabled, the file watchers tail harness logs from `~/.glove/envs/<env-id>/home/` alongside native ones, and sandboxed sessions are tagged with their environment id via the existing `sessionName` field so they are distinguishable from native ones without displacing them. It is read-only "outside looking in" - nothing is written into a sandbox, no egress is added, and the docker-compose mount is `:ro` - which is a faithful fit for glove's security model. Only harnesses that persist a tailable transcript are discovered (Mistral Vibe and pi); network-hook harnesses (codex, cline, opencode) POST *to* Layman, which a net-restricted sandbox cannot reach, and monitoring those from a sandbox is a separate mechanism, not this one
- Generalised the passive file watcher's single hardcoded log root (`~/.vibe/logs/session`) into a list of `MonitorSource`s (`monitor/sources.ts`), re-queried on every scan tick, so the native root and any number of glove sandbox roots are watched at once and appear or disappear dynamically without a restart. Each root carries its agent type and an optional sandbox label, which a session inherits; the watcher's Vibe-specific parsing is unchanged, so this is purely about *where* it looks, leaving *how* it parses for a future passive harness to extend. Native monitoring is byte-for-byte unaffected whether or not glove is enabled
- Fixed red-level drift saying nothing at all to a harness Layman may not block, which inverted the severity ordering: with approvals off, which is pi's default, orange produced a reminder and red - strictly worse - produced silence. `checkPreToolUse()` returns "block" and "remind" as alternatives rather than as levels, returning early at red, so a red result that could not be acted on fell past both branches to the plain auto-allow return and discarded the reason with it. A block that cannot be honoured is now demoted to a reminder carrying the same text, and records the `drift_alert` the block branch would have. The comment claiming this already happened was wrong rather than the code, which is why the case had no test
- Fixed a trailing reasoning-only assistant message blanking a turn's answer. A reasoning model emits one assistant message per tool-calling step and pi records those for their reasoning alone - empty text with `thinking` set - while turn extraction took the *last* `agent_response` unconditionally, so an aborted or tool-terminated turn rendered a blank response in the transcript, the markdown export, TTS and the dashboard alike. The turn's response is now the last one that actually said something, falling back to a reasoning-only message only when the turn produced nothing else, so its reasoning is still shown. Fixed in both hand-mirrored copies of the rule, with matching tests
- Fixed auto-speak in `final` mode silently swallowing a turn that ended with a reasoning-only message. Every `agent_response` supersedes the pending candidate and restarts the two-second debounce, so a message pi recorded for its reasoning alone displaced the real answer and then spoke nothing at all. A message with nothing to say is no longer a candidate. The turn-header speaker button was already correct, since it reads the turn's response rather than the event
- Fixed a reasoning-only message also rendering an empty `RESPONSE` row beneath its reasoning row in Logs - once every tool call, on a reasoning model. The derived reasoning row is the whole message in that case, so it now takes over the real event id and replaces the row rather than preceding it, which leaves scroll-to, expansion, row numbering and pairing resolving by id exactly as before
- Fixed a straggling token delta for an *older* message still resurrecting a live row. Closed messages were remembered one per session, so a delta for message A arriving after B had opened and closed passed the guard and was treated as new - recreating precisely the phantom row the guard exists to prevent. Closures are now remembered per message, and a `done` for one message also marks whatever it superseded as closed
- Fixed **Expand all** in Logs leaving every derived reasoning row collapsed while the button relabelled itself **Collapse all**. The expandable-row list was built from real events and so could never contain a derived row, while the rows themselves were marked expandable separately; both now come from the same display list
- Fixed the OpenCode plugin retaining each streamed part's full accumulated text for the life of the session when a message ended on a tool call or was aborted, since the only pruning path ran on a terminal step. Streaming bookkeeping is now also dropped when a turn goes idle or its session is deleted, at which point no part can grow again
- Fixed `LiveStreamStore.stop()` never being called, leaking its sweep interval for any process that creates and tears down more than one server
- Fixed a history scan duplicating every event of a pi session that Layman had already monitored live. Enrichment for a harness with no `parseAfter` fast path re-parsed the whole transcript and relied on `importSession()`'s `INSERT OR IGNORE` to skip what was recorded, but that only dedupes on matching ids: live events are stored under `randomUUID()` while the parsers mint deterministic ids from the transcript, so nothing collided and **Settings -> Data -> Scan now** inserted a second full copy. Sessions recorded live are now skipped by that path outright, and the fallback filters against the recorded ids explicitly rather than trusting the upsert. The regression test that should have caught this was seeding "live" events with the parser's own ids, which is not what live recording does
- Fixed the enrichment result reporting a session's whole-file tool-call and prompt counts alongside a delta event count, so the Import dialog showed rows like `3 events / 200 tool calls`. All three counts now describe the same set of added events
- Fixed `Grep` and `Glob` calls summarising as the directory they searched rather than the pattern they searched for. The cross-harness path helper resolves `path` (which is what pi names its file argument) ahead of `pattern`, and claude-code uses the same key for a search *root* - so every search in a session rendered as the same repository root, in the Logs rows, the dashboard tail, the event detail and the markdown export alike. Search tools are now excluded from path resolution, which also makes the existing `pattern` fallback reachable
- Fixed a straggling token delta reopening a live stream that had already been closed. A producer's final delta flush and its `done` flush are independent posts with no ordering guarantee - pi's `message_end` fires both back to back - and when `done` won the race the late delta was treated as a new message, recreating the row and broadcasting `stream:update` after `stream:end`. For an assistant message that was nothing but tool calls no committed response ever follows to clear it, so the phantom row survived until the 60s idle sweep. Closed messages are now remembered for the length of that sweep window and their stragglers dropped
- Fixed the live token counter never showing anything. Nothing populated it: no harness reports usage *during* generation - pi and OpenCode both attach it to the finished message, by which point the live row is gone - so the count sat at zero for the entire life of every stream and its render branch was dead code. It is now derived from the accumulated output and rendered as `~1.2k out` to mark it an approximation, with a figure reported by a producer superseding it
- Fixed a live row surviving a harness quit mid-generation, showing "responding…" with a blinking caret for up to 60s. The extension's closing delta goes out through the same fire-and-forget path as everything else and is dropped by the exiting process - which is precisely why `SessionEnd` is the one post it awaits - so the server now closes the session's live stream on `SessionEnd` rather than trusting that delta to arrive
- Fixed pi's session metrics bar going blank moments after it populated. pi names a session shortly after its first turn, and the extension answered that by posting a `StatusLine` containing only the new name; the client replaces its metrics entry wholesale rather than merging, so model, cost, tokens and context fill were all cleared. The rename now carries the full payload
- Fixed orange-level drift reminders never reaching pi. The reminder rides back on `permissionDecisionReason`, but a harness Layman may not block skipped that branch and returned a bare `{}` - so with approvals off, which is pi's default, the drift monitor reported a reminder to nothing at all. The reminder is now returned on the auto-allow path too, and the extension surfaces an allow-with-reason through pi's own notification UI instead of discarding it
- Added historical session import for pi - **Settings -> Data -> Import session history** now discovers `~/.pi/agent/sessions/` alongside Claude Code's `~/.claude/projects/` and imports whatever wasn't monitored live. pi's session files are format-version-3 JSONL *trees* (`id`/`parentId` links, not a flat sequence, since pi branches in place on `/fork` rather than starting a new file), so the importer walks from the latest-timestamp leaf back to the root and imports only that path - a flat read would have replayed abandoned branches as though they happened. Discovery, parsing, and import were generalised into a small per-harness registry (`TranscriptSource`) in `recovery.ts` first, as its own change, specifically to remove the two hardcoded `'claude-code'` literals that would otherwise have silently mis-attributed every imported pi session the same way the `handler.ts` agent-type allow-list already warns about. The Import dialog gained a Harness column now that a scan can mix sessions from more than one client
- Added a `parseAfter?()` capability to `TranscriptSource` for cheap incremental enrichment of an already-recorded session (claude-code has this; pi doesn't yet, since its tree structure doesn't map onto a flat timestamp cutoff) - a source without it still enriches correctly, just via a full re-parse routed through the existing idempotent `importSession()` upsert instead of a fast path
- Added [pi](https://pi.dev) as a supported harness, integrated through a TypeScript extension rather than shell hooks. pi auto-discovers `~/.pi/agent/extensions/*/index.ts` and loads it with jiti, so installation is a single file with no config to mutate, no build step, and no `node_modules` beside it; **Settings -> Harness -> Install** writes it through a new `~/.pi` bind mount and `/layman` activates a session. The extension has no imports at all - not even `import type` - because jiti would erase them at runtime but they would still force this repo to depend on `@earendil-works/pi-coding-agent` just to typecheck. pi separates reasoning from response text at the protocol level, so `data.thinking` is populated directly and none of the `<thinking>`-tag heuristics other harnesses need are involved
- Added live token streaming - partial assistant output, text and reasoning separately, pushed to the dashboard as it is generated, with a token counter that ticks during generation and a live row that is replaced by the committed response when the turn ends. Wired for pi (token-level, thinking as its own stream) and OpenCode (token-level, `reasoning` parts); the four harnesses with no streaming hook render no live row at all rather than an empty or stuck one. Deltas deliberately bypass `EventStore` - a local model emits thousands per turn, and PII-scanning, ring-buffering, persisting and broadcasting each one is ruinous - so they go to a dedicated store and dedicated `stream:update`/`stream:end` WebSocket messages, following the `session_metrics` precedent. Two toggles under **Settings -> Stream behavior**, both enforced server-side so turning the feature off stops the data being sent rather than merely hidden
- Added PII redaction for streamed output, applied to the accumulated buffer rather than to each delta. A secret such as an API key or JWT routinely straddles a delta boundary, where neither half matches the pattern on its own, so per-delta filtering would pass it through whole
- Added opt-in tool approval for pi, off by default and toggled per-harness in **Settings -> Harness**. pi's stated design position is that a coding agent should not impose permission popups, so blocking it by default would override that choice on the user's behalf; offering it as a toggle is a faithful reading of the same position. The decision is evaluated server-side on every tool call rather than told to the extension at startup, so flipping the toggle takes effect on the next tool call with no pi restart. The drift monitor's red-level block is gated by the same check, since it suspends the agent through `PendingApprovalManager` too and would otherwise block pi through a second door while the toggle read "off"
- Added `thinkingLevel` to session metrics - pi reports its current reasoning effort, which is a per-session setting the user changes and, on a local reasoning model, the main explanation for a swing in output tokens and latency
- Fixed the session metrics bar showing a permanent `$0.0000` for locally hosted models, which have every cost field set to zero. Cost is now shown only when non-zero, so the numbers that actually move - tokens and context fill - keep the prominent position
- Generalised the prompt relay from `/api/opencode/pending-prompt` to `/api/prompts/pending`, so pi sessions accept prompts submitted from the dashboard. The `/api/opencode/*` paths are kept as aliases rather than redirects: an OpenCode plugin installed before this change is a file on the user's disk that polls the old path until the user reinstalls, and breaking it would silently kill prompt submission for existing users
- Added a `tagStyle` option to the client installer. Every installed file carries a trailing `layman:<hash>` version tag for staleness detection, written as an HTML comment - which is a syntax error in a TypeScript file, as pi's extension is. Those now get a `//` line comment instead
- Changed the installer's content hash to cover the settings baked into an integration, not just its source. pi's extension embeds the server URL and the approval timeout, so changing either now correctly reports the install as out of date instead of leaving it green while pointing at an unreachable URL
- Fixed `getStatus()` throwing and breaking the entire Settings page for every client when one client's template file was missing - an image built before a template was added would take the whole page down rather than that one row
- Corrected the documented Codex activation token from `@layman` to `$layman`, which is what the handler has always matched, and the harness docs' **Settings -> Connection** references to **Settings -> Harness**, which is the section's actual title

- Fixed a PII leak in layman's-terms explanations - `EventStore.attachLaymans()` set `event.laymans` directly with no redaction step, unlike `event.data` which always passes through the PII filter. An unfiltered explanation could end up in a session's markdown export or be read aloud by text-to-speech. `EventStore` now takes a `setStringFilter()` hook (wired to the same `redactString()` used elsewhere) and applies it to the explanation before it is stored
- Fixed clicking a collapsed-duplicate `user_prompt` row expanding a different, unclicked row instead - `pairFor()` paired on the turn's canonical `promptEventId` rather than the id of the row actually clicked, so of the ~800 duplicate prompt rows left over from the hook double-registration bug, clicking one silently expanded the surviving original instead
- Fixed a deep link to an archived session's Logs/Flow view (`/s/{id}/t/{turn}?view=logs`) rendering blank when the session isn't present in the live WebSocket-fed event store (server restarted, or the session ended long ago) - `useEventStore()` now falls back to `historicalEvents` (already fetched by `hydrateFromRoute`) when the live, `activeSessionId`-filtered event list is empty
- Fixed the single-turn markdown export (`GET /api/turns/:sessionId/:promptEventId?format=md`) silently dropping tool-call and explanation sections for a live session not yet persisted to SQLite - the route read events straight from `BookmarkStore` (SQLite-only), instead of through `TurnStore`'s existing live-store fallback. `TurnStore.eventsFor()` is now exposed for the route to reuse
- Fixed the exported tool-call summary (`describeToolCall` in markdown export) picking a different field than the live dashboard when a tool input has both `url` and `query` set - the two implementations checked candidate keys in a different order. Reordered to match `EventCard.tsx`'s `formatToolInput()` exactly and dropped a `path` key the client never looks at
- Fixed `GET /api/resolve`'s 409 "ambiguous id prefix" response being treated the same as 404 "not found" on the client, discarding the candidate list the server computed - a shortened highlight/bookmark/folder link that collides with another entity's prefix now reports that the id is ambiguous instead of claiming the entity doesn't exist
- Fixed `expandHome('~')` being a no-op - the PII filter redacts a session `cwd` that is exactly the home directory to the bare string `~` (no trailing slash), which the `~/`-only check left unexpanded, silently dropping that session's directory from `trackedCwds()` and breaking hook-repair routes scoped to it
- Fixed `GET /api/resolve`'s prefix lookup forcing a full table scan of `recorded_events` - the largest, unbounded table - because SQLite disables the `LIKE`-to-index-range-scan optimization by default whenever the pattern contains letters under case-insensitive `LIKE` semantics. Prefix matching now uses a direct `col >= prefix AND col < successor` range comparison, which is index-eligible unconditionally
- Removed a duplicated `TOOL_CALL_TYPES` set in `export/markdown.ts` that could silently drift from the same set in `turns/extract.ts`, making the turn header's tool-call count and the markdown export's count disagree if only one copy were updated
- Fixed a database corruption risk - the recorded-session database ran in SQLite's WAL mode, which depends on an mmap-coordinated `-shm` file and correct cross-process file locking. `~/.claude/layman.db` is reached through a bind mount, and on macOS that is FUSE-backed and provides neither reliably. It now uses `journal_mode = DELETE`, which costs write concurrency Layman does not use (one writer, one small row per hook event). A database damaged this way is recoverable with `sqlite3 .recover` - see the runbook in `docs/development.md`
- Added text-to-speech via [speaches](https://github.com/speaches-ai/speaches) - agent responses can be read aloud, with a speaker button on every turn header, agent response row and highlight, and an optional auto-speak mode. Off by default; enable it under Settings → Data → Text to speech. Auto-speak has two modes: `final` waits for a two-second pause so only the answer is read rather than every interstitial message between tool calls, and `all` reads every response in order. Speech is strictly serial - one utterance at a time, FIFO, deduplicated by event id - and a compact transport in the status bar shows what is playing, the queue depth, and skip/stop/mute
- Added `?play=1` support - opening `…/s/{sessionId}/t/{promptEventId}?play=1` (or `/h/{highlightId}?play=1`) hydrates that turn and reads its response aloud. This is what makes a link in an exported note actionable: click it and the answer is spoken. Browsers refuse programmatic audio until the page has been interacted with, so a link opened in a fresh tab surfaces a one-click "Enable audio" prompt in the status bar with the turn already queued, rather than failing silently. `?play=1` is consumed on arrival and never re-emitted into the address bar
- Added TTS proxy routes - `POST /api/tts/speech` (streams audio), `GET /api/tts/voices`, `GET /api/tts/models`, `POST /api/tts/test`. Requests go through Layman rather than straight from the browser because speaches disables CORS unless started with `allow_origins`, and proxying also keeps the optional speaches API key out of client code. A `direct` toggle bypasses the proxy for users who have configured `allow_origins`. `localhost` in the endpoint is rewritten to `host.docker.internal` when Layman runs in Docker, reusing the existing helper
- Added two independent speech-rate controls, because speaches has no pitch parameter - `speed` is sent upstream and changes tempo with the voice's pitch preserved, while `playbackRate` is applied to the audio element in the browser and, with "preserve pitch" off, pitch-shifts as well. The speed slider is capped at speaches' own accepted range (0.5×–2×) so it cannot produce a value the server rejects
- Added speech text sanitisation - fenced code is replaced with "code block" or skipped, links are reduced to their text, bare URLs become "link", and headings, tables, bullets and stray HTML are flattened to prose. Emoji and markdown emphasis are deliberately left alone, since speaches already strips those. Text is capped on a sentence boundary rather than mid-word
- Added client-side routing for the addressable URLs - deep links now actually navigate. Loading `/s/{sessionId}`, `/s/{sessionId}/t/{promptEventId}`, `/s/{sessionId}/e/{eventId}`, `/h/{highlightId}`, `/b/{bookmarkId}` or `/f/{folderId}` restores that exact view (live or historical), and the address bar tracks navigation as you move around, so the URL is always shareable. `?view=` opens a route in a specific surface (`dashboard|logs|prompts|flow|sessions`). An unknown id renders a "Not found on this instance" panel that names the instance and offers a search box, rather than a blank screen
- Added copy-link buttons on every addressable surface - session header, each turn header, highlight detail, expanded log rows, and dashboard session cards. Links are built from `publicUrl`, falling back to the browsing origin, so a hub browsed over the LAN emits its own hostname rather than `localhost`
- Added a turn ruler to the session transcript - one collapsible header per turn showing `#index · prompt first line · start · duration · N tool calls`, with a copy-link button and a "no response" marker for turns the agent never answered. Collapsing a turn hides its events but keeps the header. Opt-in per view, so the live Logs list keeps its current density
- Fixed duplicate `user_prompt` rows producing phantom empty turns - the now-fixed hook double-registration bug left ~800 duplicated prompts in recorded history, each of which opened an empty turn that stole the previous turn's trailing `agent_response`. Turn extraction now collapses identical prompts recorded within 1s of each other into one turn (measured: 741 same-text pairs land <100ms apart, while genuine re-sends are 1s+ apart). Links minted against a collapsed duplicate still resolve to the surviving turn. One real session went from 188 prompt rows / ~70 responseless turns to 119 turns / 5 responseless
- Fixed the Prompts view's "Open session" never scrolling to the highlighted pair - `bookmarksScrollToEventId` was set by the navigation action but no component consumed it
- Extended `GET /api/resolve` to report the session a bookmark or highlight belongs to (and the turn a highlight names), so `/b/` and `/h/` links can be resolved to a navigable location in one request
- Added a turn model and addressable URLs - a *turn* (one user prompt, everything it owns up to the next prompt, and the final `agent_response` in that window) is now a first-class server-side entity with its own read API (`GET /api/sessions/:id/turns`, `GET /api/turns/:sessionId/:promptEventId`, `GET /api/sessions/:id/export`, `GET /api/resolve`) and a canonical URL grammar (`/s/{sessionId}/t/{promptEventId}`, plus `?view=`, `?play=`, `?t=`). Ids may be given as an unambiguous prefix of 8+ characters. Markdown and JSON export share one serializer; the JSON form is exactly what `POST /api/bookmarks/sessions/import` accepts, so export/import round-trips. Added a SPA fallback route so deep links survive a page reload
- Fixed Layman hooks being registered twice, causing every hook event to fire and be recorded twice - `install()` identified its own hooks by the `_layman` tag or an exact `serverUrl` match, but claude-code strips unknown keys when it rewrites `settings.json`, so the tag never survived, and any URL change (port, `--hook-url`, `localhost` vs `host.docker.internal`) stopped the exact match from working and appended a duplicate hook set instead of replacing it. Hooks are now identified structurally by URL shape (`{origin}/hooks/{KnownEvent}`), making install idempotent and self-healing across URL changes
- Fixed hook removal deleting unrelated hooks - the install/uninstall filter dropped whole matcher objects when any hook inside looked like Layman's, taking a user's own hook down with it if the two shared a matcher; entries are now filtered individually
- Added `layman repair-hooks [dir] [--dry-run]` - removes orphaned project-level Layman hooks left in `<project>/.claude/settings.local.json` from before Layman moved to a global install. claude-code merges project settings on top of global ones, so these leftovers doubled every event. Only Layman's own entries are removed; all other keys and any foreign hooks are preserved, and the file is never deleted. Implemented as a CLI command because the Docker container mounts only `~/.claude` and friends and cannot see a project's `.claude` directory

## 0.8.1

- Added expanding interface - progressive panel disclosure for Dashboard/Logs/Investigation driven by content-measured thresholds, with drag-to-resize dividers, independent Dashboard/Logs tab toggling, and a restored kind-colored Minimap; Logs rows now use the Dashboard's flat single-line vocabulary (expand/collapse, Highlight/Copy/Investigate) instead of exchange-tree grouping ([#77](https://github.com/castellotti/layman/pull/77))
- Fixed PII filter regressions found in review of #74 - home-directory redaction no longer swallows trailing punctuation or the dots in usernames, forward-slash Windows paths (`C:/Users/alice`) are fully redacted instead of leaving a dangling prefix, and a raw, unfiltered `cwd` was no longer embedded in the session-summarize prompt sent to the external LLM ([#76](https://github.com/castellotti/layman/pull/76))
